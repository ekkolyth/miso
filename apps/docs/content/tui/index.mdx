# Terminal UI (TUI)

Miso includes a built-in terminal UI for running multiple scripts concurrently — similar to Turborepo's TUI but with per-process restart and two display modes.

## Two Modes

### Tabbed Mode

A sidebar lists your workspaces/scripts with status indicators. Select one to see its full log output. Navigate with arrow keys, restart individual processes with `r`.

### Merged Mode

All logs stream together in one view with color-coded labels per workspace. A filter bar lets you toggle which workspaces are visible.

## When to Use

- **Monorepo development** — run `dev` scripts across all workspaces simultaneously
- **Single repo with multiple services** — run your app server and a backend like Convex side by side
- **Build ordering** — run builds in dependency order across workspaces with `dependsOn`
- **Turbo/Nx delegation** — use miso's UI while Turbo or Nx handles orchestration

## Quick Start

Add `"tui": "tabbed"` (or `"merged"`) to your `miso.json`:

```json
{
  "package-manager": "bun",
  "tui": "tabbed"
}
```

Then run any script from the project root:

```bash
miso dev
```

Miso discovers all matching scripts and launches the TUI.

## Dependency Ordering

For build commands that need to run in order, configure `dependsOn` in the `repo` field:

```json
{
  "package-manager": "bun",
  "tui": "tabbed",
  "repo": {
    "mode": "mono",
    "tasks": {
      "build": { "dependsOn": ["^build"] }
    }
  }
}
```

The `^` prefix means "run this task in upstream workspace dependencies first." Miso reads the dependency graph from each workspace's `package.json` and executes in topological order.

## Working with Turbo / Nx

You can delegate orchestration to Turborepo or Nx while still using miso's TUI:

```json
{
  "package-manager": "bun",
  "tui": "tabbed",
  "repo": "turbo"
}
```

Set `"repo"` to `"turbo"` or `"nx"`. Miso spawns the underlying tool as a single process, parses its output, and displays it in the TUI with per-workspace tabs.

## Auto-Exit

When all processes complete, the TUI waits 2 seconds (so you can see final status) then exits automatically. If any process failed, a summary is printed to stderr.
