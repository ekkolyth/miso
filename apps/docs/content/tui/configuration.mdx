# Configuration

### `tui`

Controls how concurrent scripts are displayed.

<Terminal
    copy={false}
    className="mt-4"
    title="miso.json"
    config={`"tui": "off" | "tabbed" | "merged"`}
/>

<DocProp prop='"off"' />
<Badge
    variant="default"
    className="bg-primary-900 font-bold text-primary-400 border-primary-400"
>
    Default
</Badge>

No TUI. Normal single-process execution.

<DocProp prop='"tabbed"' />

Sidebar with workspace list, selected workspace's logs on the right. See [Tabbed Mode](/tui/modes#tabbed-mode).

<DocProp prop='"merged"' />

Interleaved log stream with colored labels and filter toggles. See [Merged Mode](/tui/modes#merged-mode).

You can also use the object form for additional options:

<Terminal
    copy={false}
    className="mt-4"
    title="miso.json"
    config={`{
  "tui": {
    "mode": "tabbed",
    "cleanExit": true
  }
}`}
/>

<DocProp prop="mode" />

TUI display mode. Accepts `"off"`, `"tabbed"`, or `"merged"`.

<DocProp prop="cleanExit" />

When `true`, suppresses the log dump on TUI exit. By default, all buffered output is printed to stdout when the TUI exits.

### `repo`

Controls how miso discovers and orchestrates workspaces.

<Terminal
    copy={false}
    className="mt-4"
    title="miso.json"
    config={`"repo": "miso" | "turbo" | "nx"`}
/>

<DocProp prop='"miso"' />
<Badge
    variant="default"
    className="bg-primary-900 font-bold text-primary-400 border-primary-400"
>
    Default
</Badge>

Miso orchestrates directly. Workspace membership is auto-detected — independent of this setting — from a `pnpm-workspace.yaml` (checked first) or a `workspaces` field in your root `package.json`. Uses `concurrent` in task config for companion scripts.

<DocProp prop='"turbo"' />

Delegates orchestration to Turborepo, miso provides the TUI. `turbo` must be available in your PATH.

<DocProp prop='"nx"' />

Delegates orchestration to Nx, miso provides the TUI. `nx` must be available in your PATH.

You can also use the object form to configure per-task behaviour:

<Terminal
    copy={false}
    className="mt-4"
    title="miso.json"
    config={`{
  "repo": {
    "mode": "miso",
    "tasks": {
      "build": {
        "dependsOn": ["^build"]
      },
      "dev": {
        "concurrent": ["db:convex", "docker:run"]
      }
    }
  }
}`}
/>

<DocProp prop="dependsOn" />

Tasks to run before this one. A bare `name` runs in the dependent's own workspace, whichever list declares it: `web`'s `dev` depends on `web`'s `name`, and a root script on the root's. A workspace without that script is skipped. `#name` resolves at the repo root, and `@member/script` resolves inside the named workspace member. `^name` runs `name` in the workspace members this member depends on, reading the graph from each member's `package.json`; an upstream member without that script is skipped.

Dependencies are followed transitively, and each script runs once per run even when several tasks depend on it. Each dependency must exit 0 before anything depending on it starts; independent ones run in parallel. A failure stops the run — dependents never start, and their tab shows as skipped. A `#name` or `@member/script` entry that resolves nowhere fails the launch. A task entry with only `dependsOn` and no script of its own runs its dependencies. A dependency's own `concurrent` list does not attach — companions start only for the task you invoked. This all works in simple mode too.

<DocProp prop="concurrent" />

Companion scripts run alongside the main task in the shared TUI. Three forms: a bare `name` resolves in the scope declaring it (root list → root, a member's list → that member), `#name` resolves at the repo root explicitly, and `@member/script` resolves inside the named workspace member. The root list spawns once per run — including during member fan-out — and an entry that resolves nowhere fails the launch. In turbo/nx mode, declaring a task here opts it into miso's direct orchestration instead of delegation. Full grammar in [Monorepos](/scripting/monorepos).

Commands not listed in `tasks`, or listed without `dependsOn`, run every matching script in parallel.
