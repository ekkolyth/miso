# Configuration

## `tui` Option

Controls how concurrent scripts are displayed.

| Value | Description |
|-------|-------------|
| `"off"` (default) | No TUI. Normal single-process execution. |
| `"tabbed"` | Sidebar with workspace list, selected workspace's logs on the right. |
| `"merged"` | Interleaved log stream with colored labels and filter toggles. |

```json
{
  "tui": "tabbed"
}
```

### Object Form

For additional options, use the object form:

```json
{
  "tui": {
    "mode": "tabbed",
    "cleanExit": true
  }
}
```

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `mode` | string | `"off"` | TUI display mode: `"off"`, `"tabbed"`, or `"merged"` |
| `cleanExit` | boolean | `false` | When `true`, suppress log dump on TUI exit. By default, all buffered output is printed to stdout when the TUI exits. |

## `repo` Option

Controls how miso discovers and orchestrates workspaces.

### String Form

| Value | Description |
|-------|-------------|
| `"single"` (default) | Standard project. Uses `multi` config for concurrent scripts. |
| `"mono"` | Monorepo. Miso discovers workspaces and orchestrates scripts. |
| `"turbo"` | Monorepo. Delegates orchestration to Turborepo, miso provides the UI. |
| `"nx"` | Monorepo. Delegates orchestration to Nx, miso provides the UI. |

```json
{
  "repo": "mono"
}
```

### Object Form (with task configuration)

For dependency-ordered execution, use the object form with `tasks`:

```json
{
  "repo": {
    "mode": "mono",
    "tasks": {
      "build": { "dependsOn": ["^build"] },
      "dev": {}
    }
  }
}
```

The `tasks` key maps command names to task configuration. Each task supports:

- **`dependsOn`** — array of strings. The `^` prefix (e.g., `"^build"`) means "run this task in upstream workspace dependencies first," reading the dependency graph from each workspace's `package.json`.

Commands not listed in `tasks`, or listed without `dependsOn`, run all workspaces in parallel.

The object form is only valid when `mode` is `"mono"`. Turbo and Nx modes do not support `tasks` — they delegate all orchestration to the underlying tool.

### Turbo/Nx Delegation

When using `"turbo"` or `"nx"` mode:

- Miso spawns the underlying tool as a single process (`turbo run <script>` or `nx run-many --target=<script>`)
- Output is parsed and displayed in the TUI with per-workspace tabs
- Workspaces are discovered dynamically as output arrives
- Individual process restart (`r`) is disabled — only full restart (`R`) is available
- The underlying tool handles dependency ordering, caching, and parallelism

**Requirements:** The `turbo` or `nx` binary must be available in your PATH.

## `multi` Option (Single Repos)

Maps a command name to multiple scripts for concurrent execution. Only used in single repos — ignored in monorepos where workspace auto-discovery provides the script list.

```json
{
  "tui": "tabbed",
  "multi": {
    "dev": ["dev:app", "dev:convex"],
    "build": ["build:client", "build:server"]
  }
}
```

Running `miso dev` with this config launches both `dev:app` and `dev:convex` in the TUI.

## Script Discovery

### Monorepos

When `repo` is `"mono"`, `"turbo"`, or `"nx"`, miso auto-discovers scripts across all workspaces:

1. Reads workspace globs from root `package.json`
2. For each workspace, finds matching scripts in both the scripts folder and `package.json`
3. Prefix matching: `miso dev` matches `dev`, `dev:convex`, `dev:worker`, etc.

### Single Repos

Uses the `multi` config to determine which scripts to run concurrently. Scripts are resolved through the scripts folder first, then `package.json`.

If no `multi` entry exists for the command, the script runs normally without the TUI.
