# Package.json Integration

Miso seamlessly integrates with package.json scripts, providing a unified interface for all your project commands. You can use both scripts folder scripts and package.json scripts together.

## How It Works

Miso falls back to package.json scripts when a command isn't found in built-in commands or the scripts folder:

```json
{
  "scripts": {
    "dev": "vite",
    "build": "tsc && vite build",
    "lint": "eslint .",
    "test": "vitest"
  }
}
```

Run these scripts with Miso:

```bash
miso dev
miso build
miso lint
miso test
```

## Benefits

### 1. Unified Interface

Use the same command syntax for all scripts, regardless of where they're defined:

```bash
miso dev           # Could be scripts/dev.sh or package.json
miso build         # Could be scripts/build.sh or package.json
miso custom-task   # Could be anywhere
```

### 2. Package Manager Agnostic

Miso automatically detects and uses your package manager:

```bash
# Works with npm, pnpm, yarn, or bun
miso dev

# Miso runs:
# - npm run dev
# - pnpm run dev  
# - yarn dev
# - bun run dev
```

### 3. Seamless Migration

Start with package.json scripts and migrate to scripts folder as needed, without changing your workflow.

## Execution

Package.json scripts execute via your configured package manager:

```json
{
  "scripts": {
    "dev": "vite --port 3000"
  }
}
```

```bash
miso dev --host
# Executes: pnpm run dev --host
# Which runs: vite --port 3000 --host
```

### Argument Passing

Arguments are forwarded to the package manager's run command:

```bash
miso test --watch --coverage
# Executes: pnpm run test --watch --coverage
```

## Scripts Folder vs Package.json

### When to Use Scripts Folder

Use the scripts folder when you need:

- **Complex logic**: Multi-step processes, conditional execution
- **Different languages**: Python, Ruby, or other languages
- **Better organization**: Subdirectories for grouping related scripts
- **Reusable helpers**: Shared utilities across scripts

Example:
```bash
#!/bin/sh
# scripts/deploy.sh

ENV=$1
if [ -z "$ENV" ]; then
  echo "Error: Environment required"
  exit 1
fi

echo "Building for $ENV..."
npm run build

echo "Deploying to $ENV..."
if [ "$ENV" = "production" ]; then
  # Production-specific steps
  npm run build:optimize
  scp -r dist/ production:/var/www
else
  # Staging steps
  scp -r dist/ staging:/var/www
fi
```

### When to Use Package.json

Use package.json scripts when you need:

- **Simple commands**: Single-line commands or npm packages
- **Standard npm scripts**: Conventional names like dev, build, test
- **Tool integration**: Direct execution of installed packages
- **Portability**: Scripts that work across all package managers

Example:
```json
{
  "scripts": {
    "dev": "vite",
    "build": "tsc && vite build",
    "lint": "eslint .",
    "format": "prettier --write .",
    "test": "vitest",
    "type-check": "tsc --noEmit"
  }
}
```

## Hybrid Approach

Use both together for maximum flexibility:

```
scripts/
  deploy/
    staging.sh      # Complex deployment logic
    production.sh
```

```json
{
  "scripts": {
    "dev": "vite",
    "build": "tsc && vite build",
    "lint": "eslint .",
    "test": "vitest"
  }
}
```

All available via Miso:
```bash
miso dev                # package.json
miso build              # package.json
miso deploy/staging     # scripts folder
miso deploy/production  # scripts folder
```

## Overriding Package.json Scripts

Scripts folder scripts take precedence over package.json scripts:

```
scripts/dev.sh exists
```

```json
{
  "scripts": {
    "dev": "vite"
  }
}
```

```bash
miso dev
# Executes: scripts/dev.sh (not package.json "dev")
```

To explicitly run the package.json version:

```bash
miso run dev
# Executes: pnpm run dev (package.json "dev" script)
```

## Listing All Scripts

View all available scripts from both sources:

```bash
miso scripts
```

Output:
```
available scripts

scripts folder:
  build (build/index.sh)
  build/miso (build/miso.sh)
  deploy/staging (deploy/staging.sh)
  deploy/production (deploy/production.sh)

package.json:
  dev: vite
  lint: eslint .
  test: vitest
```

This helps you:
- See what commands are available
- Understand which source provides each command
- Identify potential conflicts or overrides

## Migration Strategy

### From Package.json to Scripts Folder

Gradually migrate complex scripts:

1. **Start**: Everything in package.json
```json
{
  "scripts": {
    "deploy": "npm run build && scp -r dist/ server:/var/www"
  }
}
```

2. **Move to script**: Create `scripts/deploy.sh`
```bash
#!/bin/sh
npm run build
scp -r dist/ server:/var/www
```

3. **Keep both**: Script overrides, but package.json remains as documentation

### From Scripts to Package.json

For simpler scripts, move back to package.json:

1. **Start**: Complex script in scripts folder
2. **Simplify**: If it becomes a one-liner, move to package.json
3. **Remove**: Delete the scripts folder version

## Best Practices

### 1. Use Package.json for Simple Commands

```json
{
  "scripts": {
    "dev": "vite",
    "lint": "eslint .",
    "format": "prettier --write ."
  }
}
```

### 2. Use Scripts Folder for Complex Logic

```bash
#!/bin/sh
# scripts/release.sh
# Complex release process with multiple steps
```

### 3. Keep Related Scripts Together

All deployment scripts in `scripts/deploy/`, all build scripts in `scripts/build/`

### 4. Document in package.json

Even if overridden, keep package.json scripts as documentation:

```json
{
  "scripts": {
    "deploy": "# See scripts/deploy/ for deployment scripts"
  }
}
```

### 5. Consistent Naming

Use the same names across both systems:
- `dev` (not `develop` in one and `dev` in the other)
- `build` (not `compile`)
- `test` (not `tests`)
