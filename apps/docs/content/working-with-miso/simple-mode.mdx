# Standalone Mode

Miso can run without a JavaScript package manager. If you like miso's script execution, TUI, env validation, and task orchestration but your project isn't JavaScript — standalone mode is for you.

### Setup

Run `miso init` from any directory. If the scan finds no apps, or you deselect every app, miso asks how to set up:

```
? miso didn't find any apps here. How do you want to set up miso?
  ❯ Create new project
    Run in standalone mode (scripts only, no package manager)
```

When the root already has a `package.json`, only the standalone option is offered.

Select **"Run in standalone mode"** and miso will create a `miso.json` with package management disabled, plus a `scripts/` directory:

<Terminal
    copy={false}
    className="mt-4 border border-neutral-700 rounded-sm"
    title="miso.json"
    config={`{
  "$schema": "https://misojs.dev/miso.schema.json",
  "packageManager": false,
  "scripts": "./scripts"
}`}
/>

### How It Works

In standalone mode, the package-management commands and `package.json` fallback are gone. Miso's utility commands still work — `help`, `init`, `version`, `upgrade`, `completion`, `skills`, `env`, and `scripts` — and every other argument resolves as a script name from the `scripts/` folder. A standalone root still finds members (directories with their own `miso.json`), and each member runs `package.json` scripts with its own package manager. A member with `"packageManager": false` runs folder scripts only:

```bash
miso build              # runs scripts/build.sh
miso test               # runs scripts/test.sh
miso deploy/convex      # runs scripts/deploy/convex.sh
```
