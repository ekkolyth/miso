# Configuring Miso

You can edit `miso.json` directly to change its settings:

### JSON Schema (IDE Support)

Add a `$schema` property to get autocomplete and validation in VS Code, Cursor, and other editors:

```json
{
  "$schema": "https://misojs.dev/miso.schema.json",
  "scripts": "./scripts"
}
```

The schema is available at [https://misojs.dev/miso.schema.json](https://misojs.dev/miso.schema.json) — use this URL in your `miso.json` for type-safe editing.

### Scripts

Sets the path to the folder you want miso to use when you run custom scripts:

<Terminal
    copy={false}
    className="mt-4 border border-neutral-700 rounded-sm"
    title="miso.json"
    command='scripts: "./scripts"'
/>

<DocProp prop="string" />

This path is relative to the location of your miso.json file. Learn more about [Scripting in Miso](/scripting)

### Shell

Default interpreter for scripts with no shebang and no recognized extension. If not set, Miso uses `sh`:

<Terminal
    copy={false}
    className="mt-4 border border-neutral-700 rounded-sm"
    title="miso.json"
    command='shell: "bash"'
/>

<DocProp prop="string" />

Examples: `"sh"`, `"bash"`, `"zsh"`. The interpreter must be available in your PATH.

### Repo

Configure whether your project is a single project or a monorepo:

<Terminal
    copy={false}
    className="mt-4 border border-neutral-700 rounded-sm"
    title="miso.json"
    command='repo: "mono"'
/>

<DocProp prop='"single"' />

Default. Treats the project as a single repository. All scripts resolve from the root `scripts/` folder.

<DocProp prop='"mono"' />

Enables monorepo mode. Unlocks workspace-scoped script execution using the `workspace:script` syntax and automatic CWD-based scoping. Requires a `workspaces` field in your root `package.json`.

<DocProp prop='"turbo"' />

Delegates orchestration to [Turborepo](https://turbo.build). Miso spawns `turbo run <script>` as a single process and parses its workspace-prefixed output into TUI tabs. Turbo must be installed and available in your PATH.

<DocProp prop='"nx"' />

Delegates orchestration to [Nx](https://nx.dev). Miso spawns `nx run-many --target=<script>` and parses its output into TUI tabs. Nx must be installed and available in your PATH.

You can also use the object form for dependency ordering in `"mono"` mode:

```json
{
  "repo": {
    "mode": "mono",
    "tasks": {
      "build": { "dependsOn": ["^build"] },
      "dev": {}
    }
  }
}
```

The `^` prefix in `dependsOn` means "run this task in upstream dependencies first." See [TUI Configuration](/tui/configuration) for details.

When set to `"mono"`, miso reads workspace paths from your root `package.json`:

```json
{
  "workspaces": ["apps/*", "packages/*"]
}
```

See [Monorepo Scripts](/scripting/scripts-folder#monorepo) for full details on workspace script execution.

### TUI

Configure the multi-terminal UI mode for running scripts across workspaces:

<Terminal
    copy={false}
    className="mt-4 border border-neutral-700 rounded-sm"
    title="miso.json"
    command='tui: "tabbed"'
/>

<DocProp prop='"off"' />

Default. TUI is disabled — output goes to the terminal as normal.

<DocProp prop='"tabbed"' />

Shows a sidebar with your workspace list and a log panel for the selected workspace. See [Tabbed Mode](/tui/tabbed-mode).

<DocProp prop='"merged"' />

Interleaves all workspace output in a single stream with color-coded labels. See [Merged Mode](/tui/merged-mode).

### Flags

Add default flags to package manager commands:

```json
{
  "flags": {
    "install": ["--frozen-lockfile"],
    "add": ["--dev"],
    "dev": ["--env"]
  }
}
```

See [Flags](/working-with-miso/flags) for the full reference.

### Multi

Named groups of scripts to run together in the TUI:

```json
{
  "multi": {
    "web": ["dev", "test"],
    "api": ["start"]
  }
}
```

### Env

Configure environment variable validation for `miso env`:

```json
{
  "env": [
    {
      "label": "web",
      "path": ".env.local",
      "required": "all",
      "variables": {
        "PORT": "port",
        "DATABASE_URL": "url",
        "NODE_ENV": {
          "type": "enum",
          "values": ["development", "production", "test"],
          "optional": true
        }
      }
    }
  ]
}
```

- **label**: Human-readable name for this env entry (used in log output).
- **path**: Path to the `.env` file, relative to project root.
- **required**: `"all"` (every variable unless optional), `"none"`, or an array of specific keys.
- **variables**: Either an object (type validation) or array (presence only). See [Env validation](/env-validation) for the full spec.
