# Setting Up a Project

Run `miso init` to set up Miso in your project.

<CommandSelect miso="miso init" />

`miso init` scans the root, `*/`, and `*/*/` for apps (JavaScript/TypeScript, Go, Rust, C#, F#, Python, Java/Kotlin, and Laravel), then asks you to confirm which ones to run with miso. It writes `miso.json` files. The one `package.json` change is `packageManager`, set for a JavaScript/TypeScript app that has no manager (no `packageManager` field and no lockfile) after you pick one.

### Choosing Your Repo Type

Basic Setup:

<Terminal
    copy={false}
    className="mt-4 border border-neutral-700 rounded-sm"
    title="miso.json"
    config={`{
      "repo": "miso" | "turbo" | "nx"
}`}
/>

or, for more advanced setups:

<Terminal
    copy={false}
    className="mt-4 border border-neutral-700 rounded-sm"
    title="miso.json"
    config={`{
  "repo": {
    "mode": "miso" | "turbo" | "nx"
    }
}`}
/>

`repo` controls the orchestration engine, not whether the project is a single project or a monorepo — workspace membership is auto-detected from a `pnpm-workspace.yaml` (checked first), a `workspaces` field in your root `package.json`, or a `miso.json` in a directory at `*/` or `*/*/`, independent of this setting.

### Single Project

Leave `repo` unset (or `"miso"`, the default). With no workspace members detected, Miso works exactly as you'd expect — one `miso.json` at the root, one `scripts/` folder, run commands from anywhere in the project, and they'll respond the same way npm, bun, pnpm, etc would.

### Monorepo

When `miso init` finds more than one app, it lists the Workspace apps, which always run, and asks which Non-Workspace apps to include, all selected:

```md
miso found 7 apps:
Workspace (always run):
  apps/web — Typescript bun
  apps/api — Go
Non-Workspace — pick the ones to run with miso:
space to toggle • ctrl+a to toggle all • Enter to confirm • ctrl+c to bail
  [x] tools/legacy — Javascript no manager found
  [x] tools/learning — Python uv
```

**Workspace** lists apps that a workspace glob in your `package.json` or `pnpm-workspace.yaml` already matches. **Non-Workspace** lists every other app it found. Apps that need one get their own `miso.json`, and the root gets a `miso.json` last. For each selected app with no package manager, it asks `Pick a package manager for tools/legacy` and writes the choice to that app's `package.json`. Miso doesn't add a `workspaces` field to your `package.json`.

### Standalone Mode
<Terminal
    copy={false}
    className="mt-4 border border-neutral-700 rounded-sm"
    title="miso.json"
    command={`"packageManager": false`}
/>

If the scan finds no apps, or you deselect every app, `miso init` asks how to set up miso:

```md
miso didn't find any apps here. How do you want to set up miso?
Press ↑/↓ to move, Enter to confirm • ctrl+c to bail

  ❯ Create new project
    Run in standalone mode (scripts only, no package manager)
```

If you deselected every app, the title is `No apps selected. How do you want to set up miso?`. When the root already has a `package.json`, `Create new project` is left out.

Selecting `Run in standalone mode` lets you use miso's script runner, TUI, env validation, and task orchestration in any project — Go, Python, Rust, or anything else, without passing through commands to a package manager like bun, pnpm, etc.

See [Standalone Mode](/working-with-miso/simple-mode) for the more details.

### Running Commands from Anywhere

You can run Miso commands from any subdirectory within your project. Miso walks up the directory tree to find your `miso.json` at the root.

```
my-monorepo/
├── miso.json
├── package.json
├── apps/
│   ├── api/
│   │   └── scripts/
│   │       └── build.sh
│   └── web/
│       └── scripts/
│           └── build.sh
└── packages/
    └── ui/
        └── scripts/
            └── build.sh
```

### Running Workspace Scripts from Root

In a monorepo, add an `@scope` target after the script to run it in a specific workspace from anywhere:

```bash
miso build @api           # runs apps/api/scripts/build.sh
miso build @web           # runs apps/web/scripts/build.sh
miso build @ui            # runs packages/ui/scripts/build.sh
```

### Automatic Scoping from Inside a Workspace

When you're already inside a workspace directory, Miso automatically scopes to that workspace — no special syntax needed:

```bash
cd apps/web
miso build    # automatically resolves to apps/web/scripts/build.sh
```
